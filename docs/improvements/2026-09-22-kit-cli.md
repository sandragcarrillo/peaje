# Kit as a CLI: install cost for the coding agent

**Date:** 2026-09-22
**Versions:** `@peaje/cli` 1.0.0 (published), 1.0.1 (robots merge fix, pending publish), `@peaje/next` 0.1.0
**Raw data:** [`2026-09-22-kit-cli.runs.csv`](./2026-09-22-kit-cli.runs.csv) (per run, extracted from Claude Code's `result` event). Full transcripts stayed local in `/tmp/ab/results`.

## What changed

The install kit used to be one long prompt pasted into the business's coding agent: the whole `next.config.ts` with 19 rewrites, a list of 17 paths not to create, the JSON-LD block, four `<link>` tags, `robots.txt`, six curl checks and the Ora audit command. The agent had to transcribe all of it into the repo.

Now the prompt is one line that points to `npx @peaje/cli@1 init <slug>`. The CLI detects the stack and host, downloads the kit from the gateway (`/:slug/kit.json`), applies it (backup instead of delete, idempotent), and `peaje verify` measures the business domain. The instructions the agent reads (`/:slug/kit/INSTALL.md`) open with "run the CLI before reading anything and trust its JSON".

## Install session, measured

Same fixture for every run: a Next.js app router repo with an existing `rewrites()` returning an array, an i18n `middleware.ts` whose matcher swallows `/mcp`, a custom `robots.txt` with its own `Disallow` rules, and a stale `public/openapi.json`. Claude Code headless (`claude -p ... --output-format json --max-turns 40`), Sonnet 5, three runs per variant, same closing instruction ("you cannot deploy; stop when `next build` passes and summarize what is left"). Cost, turns and tokens are what Claude Code reports.

| Per install | A: old prompt | B: one line + CLI, first INSTALL.md | B2: INSTALL.md says "run the CLI first" |
|---|---|---|---|
| Turns | 19.0 | 24.7 | 10.0 |
| Output tokens | 11,582 | 8,074 | 2,699 |
| Cache read tokens | 413k | 386k | 266k |
| Cost per session | $0.269 | $0.233 | $0.118 |
| Wall time | 122 s | 89 s | 39 s |
| Correct checks (of 8) | 6.7 | 8.0 | 7.0 |

A to B2: -47% turns, -77% output tokens, -56% cost, -68% time.

## What we learned

- **The CLI alone did not save turns.** With the first INSTALL.md the agent explored the whole repo, asked for `--help` twice, ran `plan` and then `init`, and re-read the files the CLI had just written: thirteen calls before running the command. Turns went up (24.7) even though output tokens and cost went down. The saving came from the instruction to run the CLI before reading anything and trust its JSON.
- **The old prompt is not reliable.** It left the JSON-LD out in one of three runs, and none of the three set the per-bot `robots.txt` rules (expected: the old prompt had no answer-engine layer). The CLI never missed the proxy, the head block or the cleanup.
- **The one check B2 failed was robots:** the CLI left the existing `robots.txt` untouched and the agent, told to trust it, never looked. Fixed in 1.0.1: the CLI merges the bot block into the existing file with markers, keeping the site's own rules.
- **The model from the planning phase predicted 48% savings; the measurement gave 56%.** Right order of magnitude for the wrong reason: it underestimated how much an agent explores and overestimated the cost of each turn.

## Excluded and not measured

- B2 run 3 was excluded from the average: Claude Code spawned a subagent and ended the session waiting for it (4 turns, $0.236, nothing applied). The CSV keeps it, marked.
- Not measured: other models (Opus 5), other coding agents (Cursor, Codex), a session with a real deploy and live verification, and the Anthropic token count of the new prompt.
